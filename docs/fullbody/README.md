# VRMC Full Body

## 使い方

1. HTTPSまたは `npm run dev` のlocalhostで `fullbody/` を開きます。保存済みのVRMと設定を読み込み、カメラを自動で開始します。初回はブラウザでカメラの使用を許可してください。Chrome / Edgeを対象としています。
2. 右上の歯車で設定を開き、VRMを選択・ドロップします。サンプルモデルでも試せます。`fullbody/?settings=1` なら設定を開いた状態で開始します。
   「サンプルを選ぶ」から標準モデルと追加5体を切り替えられます。選択は再読み込み後も保存され、配信用ウィンドウにも反映します。「サンプル一覧・ダウンロード」から共通の `/models/` を開けます。
3. カメラや品質を変える場合は、一度「カメラを停止」して選択し直します。全身を追う場合は頭・両肩・腰・足先が映る位置に立ちます。机の前では顔・肩・手が映れば上半身を追跡できます。
4. 「正面・自然な姿勢」「目を開けて」「目を閉じて」を順に記録します。各回3秒の準備時間＋通常1.5秒の測定時間です。検出fpsが低い場合は、必要な観測が集まるまで最大6秒へ測定を延長します。目の形によって開眼が測定できない場合は、閉眼を先に記録できます。
5. 左右の目の測定値を見ながら、「開く値」「閉じる値」を微調整します。閉じる値未満は全閉、開く値以上は全開、中間は連続的に変化します。
6. OBS用には背景をグリーンにし「設定を閉じて配信画面へ」。この画面をウィンドウキャプチャし、クロマキーで背景を透過します。歯車は追跡開始後、約2.5秒操作しないと消えます。マウスを動かすかキーを押すと再表示します。操作ボタンが一切ない別ウィンドウも「配信用ウィンドウを別に開く」から使えます。

「ポーズを固定」は追跡映像に関係なくアバターを止めます。固定中はキャリブレーションできません。「PNGを保存」は操作パネル・カメラ映像・透過確認の市松模様を含めず保存します。透過背景ではPNGのアルファチャンネルを保持します。

「モーションを鏡写しにする」は、左右の腕・脚・指、頭と体の傾き、腰の左右移動、視線・左右の瞬きを鏡写しにします。初期状態はオンで、自分の右手を上げると正面のアバターは画面右の手を上げます。髪型・服・文字・体型はVRM本来の左右を保ち、画像全体を反転しません。配信用ウィンドウとPNGも同じ姿勢です。ポーズ固定中は鏡の設定を変えても固定姿勢を維持し、解除後に反映します。キャリブレーションと左右の目の調整は本人基準のままです。「カメラ映像を鏡表示」は、カメラプレビューだけの独立した設定です。

カメラプレビューは毎回非表示で開始します。「カメラ映像を表示」を選ぶと確認ダイアログが開き、承認するまで実映像は表示しません。表示先は設定パネル内だけです。設定を閉じる・カメラを停止する・初期化する・ページを再読み込みするたびに表示許可を解除します。表示許可は保存せず、追跡自体はプレビューが非表示でも継続します。

カメラが切断された場合は、追跡モデルの初期化中でも開始処理を中止し、接続切断の表示と再開操作へ戻ります。接続を確認して「カメラを開始」を押してください。プレビューの表示許可は切断時に解除されます。

## 既存アプリから引き継いだ要件

- ブラウザ上でVRMを動かし、配信画面として使用する。
- ローカルVRMのドラッグ＆ドロップとブラウザ内保存。
- 背景色の変更。Ctrl / Command＋左右矢印でも切り替え可能。
- マウスで構図を調整し、アバターだけを取り込めること。
- 静的サイトとして配信可能。全身版にサーバーの起動やアカウントは不要。

全身版は `fullbody/` に追加しています。従来の単体版・Partyの通信・Studioの複数アバター撮影を置き換えるものではなく、全身版の追跡データをPartyへ送信する機能はありません。

## トラッキングの仕様

処理の役割・座標系・時間・参考文献・回帰テストは [TRACKING_DESIGN.md](./TRACKING_DESIGN.md) にまとめています。
変更前の検討事項と配信用の受け入れ基準は [QUALITY.md](./QUALITY.md) にまとめています。

描画時の身体の追従は、位置と速度を保持する臨界減衰を使います。手首・関節・腰で共通の応答方式を使い、観測が届くたびに速度をリセットしません。低い検出fpsでは停止と再加速を減らすため応答時間を自動的に延ばします。この分の遅れはありますが、未来の動きを予測して手を動かし続けることはありません。推論そのものを高速化する機能ではありません。

Hand由来とPose由来の腕の位置は同じIKへ渡し、入力元が切り替わっても手首の位置・速度・肘の曲げ面を継続します。肘は胴体の向きに対して計算し、伸展時にも前の曲げ面を保ちます。胴体の近似領域に入る場合は、腕長と手首位置を保つ範囲で肘を外へ回します。衣服を含む厳密なメッシュ衝突や、見えない肘の実位置を保証する処理ではありません。

肘が隠れてもPoseの手首と両肩が見えていれば、Handの検出を待たずに腕IKを動かします。PoseとHandの切り替え・再検出時は目標を短く混ぜ、可視性しきい値にも開始と継続の幅を設けています。左右を確認中の側は保留します。手首の移動に伴う肘の曲げ面の変化は同じフレームに反映し、手が到着してから上腕だけが追従する二段階の遅れを抑えます。

下げた手から顔の横へ移る途中は、肩からの左右位置と上下・前後の角度・半径を追従します。肩の近くを直線で通って肘が横へ跳ね上がる軌跡を避け、体の前を通るように補間します。最終的な手首の目標位置は維持します。見えている肘は引き続き曲げ方向の手がかりに使います。

左右が一致し位置が連続する短い手検出の欠落は、確定済みのIDを引き継ぎます。左右の矛盾・長い欠落・新しい手には確認を行います。掌の回転は分配前に一度追従し、上腕・前腕・手首へ分配した後の平滑化の重ねがけをなくしています。

入力はWebカメラ1台、音声は取得しません。FaceLandmarker / PoseLandmarker / HandLandmarkerを同じ撮影フレームに適用し、顔・胴体・四肢・手指を推定します。検出はWeb Worker内、描画はメイン画面で実行し、未処理フレームを積み上げません。標準はPose Full、軽量はPose Lite。GPUの初期化に失敗した場合は、Workerを破棄してCPUで初期化し直します。

顔は変換行列の直交化から正規化クォータニオンを取得し、正面キャリブレーションとの差を使います。クォータニオンの成分に個別の倍率をかける方法は使いません。胴体・首の親の回転を取り除いてから頭に適用し、首にも一部を分配することで、回転が重複しないようにしています。

顔の検出結果は体・手の処理完了を待たずに反映します。頭の動きは「顔のなめらかさ」を基準に一度だけ平滑化し、顔の検出頻度が低い場合は同じ処理の応答時間を補います。停止と急加速の繰り返しを減らす分、低fpsでは遅れが少し増えます。体のなめらかさは重ねず、表情・瞬き・視線も顔の先行結果から更新します。全身版は同じWorkerで体と手も処理するため、顔の検出頻度そのものは顔専用の従来版より低くなる場合があります。

目はランドマークの縦横比（EAR）を用いて、左右別の開閉基準で連続的に駆動します。視線はブレンドシェイプ、欠ける場合は虹彩位置から取得し、どちらかの目が閉じ始めてから開眼後の保持時間まで直前の視線を保ちます。VRMのLookAt経由で適用し、ボーン方式・表情方式に対応。左右別blinkを持たないモデルは共通blinkで駆動します。

体は腰・肩の直交座標系と関節間の方向ベクトルから計算し、モデルの正規化ボーンと基準軸、現在の親の回転を考慮して適用します。腰が映らなくても肩と頭の位置から胴体の向きを求めます。手の左右は体側の信頼できる手首位置、直前の軌跡、左右分類を組み合わせます。画面の左右だけでは決めないため、体の前で手を交差しても左右の対応を維持します。新しく映った手や、戻った際の左右・軌跡が曖昧な手は、最低2回の観測と通常80〜160msの安定を確認してから腕へ反映します（4fpsでは通常2観測で250ms）。確認中は「左右を確認中」と表示し、不確かな体側の腕推定から逆腕が先に上がることも防ぎます。確定後も、体側の手首が一回だけ反対側を指した結果では入れ替えず、継続した根拠で訂正します。体と手の両方が反対側を示す訂正待ちには、古い側へ新しい手の位置を流しません。同じ手を二重に検出した場合は21点の位置関係で重複を除き、訂正前の腕に残っていた保持姿勢も解除します。手を下げたことが体側で確認できる場合も、古い手の位置を保持しません。検出が不確かな関節は受信後約0.4秒保持してから待機姿勢へ戻します。なめらかさは経過時間に基づくため、描画fpsが変わっても同じ時定数です。

手が検出できる場合は、画像内の手首と顔・肩の位置関係から手首の目標位置を求め、モデルの上腕・前腕の長さを使う2ボーンIKで腕を動かします。見える肘は腕を曲げる方向に使い、肘の検出の有無で別の手首位置へ切り替えません。画像内の縦横位置を優先し、奥行きは腕の届く範囲に収めます。画面座標をモデルの長さへ変換する倍率は基準姿勢の寸法から計算し、アニメーション中の回転を計算へ戻さないことで、静止した手の位置の揺れを抑えます。手のworld座標は手の中心を原点にしているため、顔・体のworld座標とそのまま足し合わせません。見えない肘の正確な位置や手の奥行きは一意には求まらないため、この補完は近似です。

「表情と口」では笑顔・驚き・怒りを個別に調整できます。笑顔は口角、怒りは眉を寄せる動き、驚きは眉を上げて目を見開く動きからモデルの表情を駆動します。口を開けて話すだけでは驚きにしません。表情全体を0にすると感情表情を止め、まばたきと口の追跡は継続します。

口は「あ・い・う・え・お」を映像の形から連続的に推定します。「い・え」は横への広がりと開口量、「う・お」はすぼめ方と開口量で分け、「う」は顎をあまり開けなくても反映します。正面キャリブレーションは口を自然に閉じて行い、通常の口幅も基準にします。5本のメーターは検出した口の形を示します。音声は取得していないため、似た見た目の発音を完全に判別するものではありません。

表情の見た目は読み込んだVRMに含まれる表情によって変わります。不足している表情や口の形は設定欄に表示します。モデルに指定された表情同士のブレンド規則は維持しており、笑顔・驚きの口の形が発音用の口を弱めるモデルもあります。

Hand / Face の点の採用条件は、有限な座標と画像内の位置です。Web版SDKがこれらの点に付ける未使用の `visibility: 0` を、Poseの可視性スコアとして判定しません。体のしきい値はPoseの点だけに適用します。この区別がないと、映像上に手の骨格が描かれていても、腕・指の計算には一つも渡らなくなります。

掌の向きは手の21点から直交座標系を求め、指は掌に対する局所的な曲げ角と開き角を各関節へ適用します。親指は付け根の対立・外転を含む3次元方向を使います。指の状態は胴体や肘の検出とは独立して更新します。VRMの基準軸と親子関係を考慮し、手首を回しただけで指の曲げ方が変わらないようにしています。

掌を返す回転は、腕の軸まわりのねじりと手首の曲げに分解します。モデルの基準姿勢を中心に前腕を100°で止める方式では、普通に手の甲を見せる動作も途中で切り詰められるため、観測した回転を周期的な角度として追従します。回転を上腕と前腕へ分配し、前腕の親に対する回転を補償することで、腕の長さ・IK手首位置・指の曲げを維持します。肘を曲げるほど上腕への追加分配を減らし、70°以上曲げた場合は掌を返すための追加の上腕回転を止めます。上腕への追加分配は120°まで、手首に残すねじりは最大30°、曲げは85°までとし、手首への回転集中を防ぎます。これはモデル変形を守るための制約で、医学的な可動域ではありません。±180°の境界で急に巻き戻らず、長く見失った後には回転履歴を再設定します。極端に手首を折り曲げる観測や、1枚の映像では向きを判別できない姿勢には限界があります。

検出座標は撮影フレームごとに1€ Filterで平滑化します。静止時の細かい揺れを抑え、移動時は追従を速くします。フィルタの時間差には撮影時刻、姿勢の保持には結果の受信時刻を使用します。推論に220msかかっても、新しく受信した結果を追跡喪失として扱いません。同じ結果を再描画するときに検出フィルタを二重に進めることもありません。カメラプレビューに検出した手の骨格、下部に検出fpsと所要時間を表示します。

体のキャリブレーションは画像中の腰の基準位置、胴体の大きさ、見えている場合の足までの高さを保存します。腰の左右移動としゃがみを推定し、床を大きく突き抜けないよう下限を設けます。足の位置を固定するIKや、前後移動の推定はありません。

## 保存と配信出力

- 設定・キャリブレーションは `localStorage`、選択したVRMは専用の `IndexedDB` に保存します。保存できない環境でも現在のセッションでは使用できます。
- カメラのデバイスIDが変わるとキャリブレーションとまぶたのしきい値を初期化します。同じカメラの設置位置や照明が変わった場合は手動で再計測してください。
- VRMファイル・映像をサーバーへ送信する処理はありません。ライブラリ・フォント・検出モデルの初回取得には通信が必要です。完全オフライン動作は保証しません。
- 配信用ウィンドウは同じブラウザ内で `window.postMessage` を通じてモデルと追跡結果を受け取ります。送信元ウィンドウとオリジンを確認します。カメラ映像は出力へ送りません。
- `fullbody/` は他の画面を必要とせず、単独でカメラ・VRM・追跡を開始します。従来の `?output=1` も単独で開けば同じように開始します。OBSなど別のブラウザ環境では、カメラの使用可否・許可とモデルや設定の保存領域も別になります。通常のChromeで使うモデル・カメラをそのまま配信するには、ウィンドウキャプチャを使ってください。
- ブラウザの透明なcanvasは、OSのウィンドウキャプチャにそのままアルファが渡る保証はありません。ウィンドウキャプチャの透過はクロマキー、画像の透過はPNGを使います。

## 制約と検証

一眼カメラによる全身の推定です。背中を向ける、手足が重なる、カメラの外へ出る、激しく動くと追跡が不安定になります。全身が映る距離では顔や指が小さくなり、近距離と同じ精度にはなりません。正確な歩行・接地・奥行き・体のひねりが必要なモーションキャプチャの代替ではありません。着席モードは脚の追跡を休止し、モデルの基準姿勢に戻します。

回帰テストは視線保持、開閉のしきい値、キャリブレーション、頭と胴体の回転、親子ボーンの変換、検出喪失、VRM 0の方向、付属VRMの正規化ボーン転送を扱います。ブラウザテストはモデルの実読み込み・透過PNG・設定保存・操作・出力画面と、合成動画およびGoogleの公式人物テスト写真を入力した実モデルの推論・CPUフォールバックを扱います。4fps・220ms遅延での腕の保持、腰のない上半身、握る・指を伸ばす動作を、読み込んだVRMの元のボーンの位置と角度まで確認します。公式の実測手ランドマークも使い、手首が回転しても指の曲げが保たれることを確認しています。掌の長軸を180°回して実VRMの掌が裏返ること、映り始めに左右分類を誤っても反対腕が上がらないことを、描画中の元ボーンの位置・向きで検証します。回帰入力には実際のJavaScript SDKが返す `visibility: 0` も保持し、検出・平滑化・手の割り当て・腕と指の反映を通して検証します。静止写真と制御した検出結果の検証では、実際の遮蔽や動作精度までは保証できません。人の全身が映った実カメラでの自然さとOBS上での取り込みは、実機での確認が必要です。

- [Unity Two Bone IK Constraint](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html): 手首の目標位置と肘の曲げ方向の分離。
