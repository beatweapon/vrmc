# 全身追跡の処理境界と連続性

## この見直しの起点

静止した手首が目標へ到達するテストだけでは、動作途中の品質を保証できなかった。
旧実装には次の相互作用があった。

- 撮影時の点のフィルタに加え、倍率・手首位置・肘方向・関節回転・前腕と上腕のねじりを別々に遅らせていた。
- 手首位置の一次遅れは、新しい観測が来る瞬間に速度が変わる。低い検出fpsでは加速と停止が繰り返された。
- Hand が欠けて Pose が見えると、IKの履歴を削除してFKへ切り替えていた。同じ動作でも二つの経路で遅れと手首位置が異なった。
- 固定のワールド座標の肘ヒントを肩→手首軸へ射影していた。体の向きが変わる場合や軸とヒントが平行になる場合の連続性、胴体との位置関係を扱っていなかった。
- 一回の手検出の欠落でも確定済みの左右を毎回確認し直し、低fpsで停止が増えていた。

## パイプラインと責任

```text
同じ撮影フレームの Face / Pose / Hand (Worker、処理中は次を送らない)
  → TrackingState: 撮影時刻で点のノイズ除去・手の物理IDと左右の確認
  → mirror-motion: 人物のモーション座標だけを反射
  → solveBody / measureHand: 観測を姿勢・手首・掌・指の制約へ変換
  → BodyRetargeter: 現在の親姿勢を解決、制約ごとに一度だけ描画時刻の追従
  → ArmMotion: 胴体座標の手首と曲げ面 → 腕長・胴体領域を満たすIK
  → bind基準から正規化ボーンのローカル回転へ変換
  → 掌回転を上腕・前腕・手首へ分配、局所的な指の曲げを適用
  → vrm.update: 正規化ボーンからrawボーン、モデルのconstraint、描画
```

顔の検出結果はPose/Handの完了を待たずに先行通知する。顔の反映だけを更新し、体と手の対応付けには引き続き同じ撮影フレームの全結果を使う。先行通知では次の撮影を開始せず、Workerの処理中状態とタイムアウトも維持する。

Hand の worldLandmarks は手の中心を原点とする。Poseの腰原点のworld座標と加算しない。
画像の縦横比を揃えた手首と顔・肩の位置関係を、VRMのbind寸法で変換する。
アバターの外観・負スケール・canvasを反転しない。左右の物理IDは鏡表示と独立。

### 時間の契約

- `captureTime`: 点のフィルタ、左右確認、検出間隔の推定。重複・逆順の撮影を採用しない。
- `time`（受信時刻）: 結果の鮮度。推論に220msかかった新しい結果を古いとして捨てない。
- `faceTime`: 顔の先行結果の受信時刻。体の受信時刻で顔の鮮度を更新し直さない。配信用ウィンドウでは顔・体それぞれの経過時間を渡して時計の原点差を補正する。
- `dt`（描画間隔）: 速度を持つ臨界減衰の追従。30/60/144fpsで同じ応答になる。
- 1€ Filterは観測ノイズの処理、`motion.js`は離散観測間の動作の処理。それぞれを一段に留める。
- 身体の応答時間は設定値と撮影間隔の1.1倍の大きい方を使う（間隔由来の下限は最大300ms）。低fpsで動きが止まる区間を減らす分、追従の遅れは増える。
- 別のスナップショットを待つバッファや、未観測の動きを予測し続ける外挿は採用しない。

`motion.js`は位置・角速度を持つ臨界減衰の解析解を使う。回転は正規化クォータニオンの最短側の誤差を回転ベクトルにし、親座標の角速度を保持する。成分ごとのクォータニオン補間ではない。
掌の向きは分配前に一度追従し、分配後の上腕・前腕・手首をさらに別々に遅らせない。
腕のIK結果へ関節ごとの平滑化を再適用しない。これにより解いた腕長と手首位置を保つ。

表情・瞬き・視線の観測処理はFaceSolverの担当を維持する。顔の表情を身体の低fps向けの応答時間で遅らせない。
頭はFaceSolverがキャリブレーション・可動域を適用した未平滑化の`headTarget`を出力し、BodyRetargeterで`faceSmoothing`に従って描画時に一度だけ追従する。そのworld回転を首と頭へ分配し、関節単位では再平滑化しない。従来互換の`head`はFaceSolver内で平滑化した値を維持するが、`headTarget`があれば重ねて使用しない。同じ撮影時刻の顔は先行通知と全結果の受信で二重に更新しない。

顔専用の従来画面と異なり、全身版は1つのWorkerでFace/Pose/Handを実行するため、顔の観測頻度は全処理時間に制約される。先行通知はそのフレームの待ち時間を削減するもので、顔専用と同じ検出fpsを保証する機能ではない。

### 頭の低fps応答の比較と採用理由（2026-09-29）

固定80msでは、4fpsの連続回転で観測間に減速し、結果到着後に急加速することを再現した。頭にもう一段フィルタを足す代わりに、同じworld回転の応答時間を `max(faceSmoothing, min(200ms, 顔の撮影間隔 × 0.65))` とする。撮影間隔は新しい顔の観測だけで更新し、既存の間隔推定と同じ25%の追従で変動をならす。既定80msなら10fps以上で補正は加わらない。表情・瞬き・視線にはこの補正を適用しない。

採用前に間隔の0.5/0.65/0.8倍を比較した。0.5倍は4fpsでまだ観測間の減速が大きく、0.8倍はさらに滑らかになるが遅れが増える。先の観測を待つ補間は4fpsで約250msの待ちを加え、予測は停止後の漂いの対処が必要になるため今回採用しない。別Workerで顔の検出頻度を上げる案はOBS併用時のCPU/GPU競合の実測が必要なため別の検討とする。

下表は0.16rad/sの合成回転、固定40msの推論待ち、60fps描画。速度は入力速度に対する倍率、遅れは同じ角度へ到達する時間差のp95。実カメラ・OBSの実測値ではない。

| 観測頻度 | 固定80msの速度p10–p90 | 修正後の速度p10–p90 | 固定80ms→修正後の遅れp95 |
| --- | --- | --- | --- |
| 4fps | 0.13–2.14 | 0.59–1.36 | 287→339ms |
| 7fps | 0.52–1.46 | 0.62–1.34 | 196→206ms |

追跡を失ってもworld回転と角速度を破棄しない。最後の有効な受信から0.4秒は目標を保持し、その後は同じ状態から応答450msで現在の胴体に対する待機姿勢へ戻す。首と頭の別々の復帰フィルタへ切り替えない。再検出時の長い撮影間隔は400msまでに制限して間隔推定を再開する。欠落を初回検出として80msへリセットせず、以降の実際の間隔へ戻す。間隔による応答の上限200msは維持する。

`tests/head-motion.test.js` は4/7/10/15/24fps、30/60fps描画、到着間隔の変動、方向反転・停止、空の検出結果と通知自体の欠落、再検出を検証する。速度分布・p95遅延・停止後の行き過ぎ・再検出時の速度に変更前に決めた上限を置く。`npm run test:head-motion` は同じ4fps入力を固定80msと現方式のサンプルVRMへ渡し、raw頭ボーンの速度を比較して `test-results/head-motion.webm` とJSON・PNGを保存する。カメラは使わない。この描画比較では速度p90−p10が0.321から0.123rad/sへ減少した。利用者のカメラ・独自VRM・OBS併用での体感は未確認。

### 腕の契約

Handがある場合の画像由来の目標、Poseの両セグメントから求めた目標、肘が隠れた場合のPose画像内の手首目標を、同じ`ArmMotion`へ渡す。Poseの手首と基準となる肩が見えていれば、Hand検出の前からIKを解く。
入力元が変わっても手首の位置・速度・曲げ面を破棄しない。どちらもないときだけ約0.4秒保持後に待機姿勢へ戻る。
入力元が変わった場合だけ、直前の目標から新しい目標へ既存の応答時間内で混ぜる。遷移中の再切り替えも、その時点の混合済み目標から開始する。追加の継続的な平滑化フィルタは置かない。
Pose手首の採用開始には通常の可視性しきい値、継続にはそれより0.1低いしきい値を使い、境界の揺れで追跡を開始・終了しない。左右確認中の側は引き続き保留し、不確かなPoseの左右で反対腕が上がることを防ぐ。
手首目標を作れず片方のセグメントだけ観測できる場合は、その関節単独の観測へ戻る。存在しない手首位置を捏造しない。

手首の追従は肩からの左右位置と、矢状面（上下・前後）の半径・角度で行う。下げた手から顔の横までxyzを直線補間すると、途中で肩との距離が縮み、IKが肘を大きく横へ逃がすため。角度の最短差を連続的に追い、下から前を通って上へ向かう経路を作る。到達後の目標位置は変えない。これは観測間の補間方式であり、カメラから実際の奥行きを復元したものではない。

IKは胴体の現在の座標系で解く。肩→手首軸が変化したら、前の曲げ面を最小回転で運ぶ。
その際、同じ肘ヒントを新旧の手首軸へ射影して、手首の移動に伴う曲げ面の変化分も同時に適用する。これを肘の平滑化へ再入力して二重に遅らせない。新しい観測による肘ヒントの変化には従来の応答を使う。射影が短い・反転する特異姿勢ではこの補正を使わず、曲げ面の保持と従来の応答で連続性を守る。
肘が観測でき、射影が十分な長さを持つ場合は観測を使う。伸び切った腕の微小ノイズで曲げ面を決め直さない。
肘ヒントが一時的に見えなくなっても約0.4秒は保持し、可視性の境界で観測と初期ヒントを往復しない。
観測のない肘の初期ヒントは下・少し外・後ろとし、前へ上がる手首より肘が先に持ち上がる曲げ面を避ける。
完全な伸展でも曲げ面の履歴を保持できるため、常に小さく曲げるための人工的な長さ制限は不要。

掌の回転を上腕へ追加分配する量は、肘の屈曲に応じて減らす。伸展から20°以内では従来の半分の分配、70°以上曲げたときは追加分配なし、その間を滑らかにつなぐ。曲げた肘のまま掌を返す動作で肩まで回るのを防ぎ、前腕側で親の回転を補償して掌の向きとIKの位置を保つ。角度と分配量はこの実装の変形調整値であり、解剖学的な可動域の指定ではない。

胴体は肩幅と胴体長から楕円体で近似する。上下端に急な段差を作らず、内部の手首目標は前面へ退避させる。
肘と腕の途中が内部に入る場合は、同じ肩・手首・腕長で可能な肘の円周上から近い安全な位置を選ぶ。
肘のxyzを直接押し出して腕を伸縮させない。この制約は衣服やメッシュ全体の衝突判定ではなく、解がない目標の完全な衝突回避は保証しない。

手の短い欠落では、位置の連続性と左右の根拠が一致すれば確定したIDを継続する。
反対の手が同じ場所へ入った場合、矛盾する左右、長い欠落では従来どおり再確認する。
左右訂正時は古い腕の位置・角速度・掌履歴を一緒に解放し、両腕に同じ手が残らないようにする。

## 参照と判断

以下は方式の参考であり、外部コードのコピーや新規ライブラリ依存の追加は行っていない。

- [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker): 画像座標と手中心のworld座標、左右分類の仕様。
- [MediaPipe Holisticの設計](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/holistic.md): Poseを利用して各部位の対応を保つ考え方。今回は検出器を交換せず、既存のPoseとHandの対応処理を維持する。
- [1€ Filter / Casiez et al.](https://gery.casiez.net/1euro/): 速度に応じた観測ノイズと遅延の折り合い。描画の速度連続性を担うものではない。
- [Daniel Holden: Spring-It-On](https://theorangeduck.com/page/spring-roll-call): 臨界減衰の解析解とクォータニオンの誤差を用いた回転追従。
- [Glenn Fiedler: Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/): 離散サンプルの位置・速度・回転と遅延の関係。4fpsでは待機バッファがさらに約250msを加えるため今回は選ばない。
- [ozz-animation IKTwoBoneJob](https://github.com/guillaumeblanc/ozz-animation/blob/master/src/animation/runtime/ik_two_bone_job.cc): 関節の座標系、曲げ軸、pole、到達距離を分けて扱う公開実装。
- [Unity Two Bone IK](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html): 手先の目標と曲げ方向のヒントの分離。
- [three-vrm VRMHumanoid](https://pixiv.github.io/three-vrm/docs/classes/three-vrm.VRMHumanoid.html): normalized/raw骨格、親子関係、更新の契約。

## 検証と限界

静止位置の一致に加え、4/10/24fpsでの上げ下げ・胸の前の交差・伸展時のノイズ・胴体の回転・Hand/Poseの交代を連続入力する。
途中の腕長、胴体の近似領域、描画フレーム間の肘/手首の移動、静止後の収束を測る。
サンプルVRMのraw骨格でもVRM 0/1の座標変換を通して確認する。
`npm run test:motion` はカメラを使わず、待機姿勢から顔の横へ手が現れる動作を実VRMで描画する。肘が手首より先に上がらないこと、途中に前方への移動があること、最終的な手首位置を検証し、正面・側面の画像を `test-results/arm-raise-*.png` に保存する。肘を曲げたまま掌を180°返す場合に、上腕へ余計な回転を加えないテストも行う。
既存の左右訂正・鏡モーション・掌の180°回転・指・表情・OBS出力・プレビューの非表示を回帰対象とする。
Hand未検出・肘が画面外でもPose手首からIKが動くこと、4/10/24fpsでのHand検出開始・欠落・再検出、Pose手首の可視性しきい値の往復も検証する。手首到着後の肘が同じ手首に対するIK解へ遅れて追従しないことと、肘ヒントが手首軸を横切る際の反転を回帰対象に含める。

Webカメラ1台では隠れた肘や奥行きを一意に復元できず、この補完は推定。
フィルタは推論fpsを増やす処理ではない。4fpsの観測から、実際の速い動作を60fpsと同じ精度で復元することはできない。
合成入力とサンプルVRMの検証を、利用者のカメラ・照明・衣服・独自VRMでの実測結果として扱わない。
