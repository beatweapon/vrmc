# vrmc

VRM.ver1.0 で配信する用のアプリケーション。
https://beatweapon.github.io/vrmc/

**全身トラッキング版 VRMC Full Body**: [`docs/fullbody/`](docs/fullbody/index.html)（公開後のURL: https://beatweapon.github.io/vrmc/fullbody/）

Webカメラ1台で顔・胴体・腕・脚・手指を追跡する、OBS配信用の単体アバター画面です。顔と首の処理は新規実装です。従来版とStudioの追跡処理はそのまま残しています。

- VRM 0.x / 1.0の選択・ドロップ、前回のモデルと調整値のブラウザ内保存。
- 瞬き中と目を開けた直後は視線を保持。左右別のまぶた感度、首・視線・口・表情の強さ、なめらかさの調整。
- 笑顔・驚き・怒りの個別調整と、見た目の「あ・い・う・え・お」の推定。
- 正面姿勢・開眼・閉眼のキャリブレーション。3秒の準備後、通常1.5秒間測定し、検出fpsが低い場合は必要な観測が集まるまで延長します。
- カメラ選択、標準／軽量モード、着席モード、手指追跡の切り替え、ポーズ固定。肘が映らない場合の手首位置と腕の補完。
- 操作パネルのない配信用ウィンドウ、透過・グリーン・ブルー・任意色の背景、透過PNG保存。アバターの鏡表示は配信用ウィンドウ・PNGにも反映します。

ローカルではリポジトリ直下で `npm ci` → `npm run dev` を実行し、http://localhost:8080/fullbody/ をChromeまたはEdgeで開いてください。静的配信なので、全身版にWebSocketサーバーは不要です。

OBSでは配信用ウィンドウを「ウィンドウキャプチャ」で選び、グリーン背景をクロマキーで透過させます。**OBSのブラウザソースに出力URLを貼る方式には対応していません**。出力ウィンドウはメイン画面から開き、メイン画面も開いたまま使います。ブラウザやOSによるバックグラウンド制限を避けるため、メイン画面は表示状態を保ってください。

全身の追跡には足先まで映るカメラ位置が必要です。机の前では顔・肩・手から上半身を追跡します。1台のカメラからの推定のため、遮蔽・背面・高速動作、遠距離の顔や指には限界があり、接地固定や正確な奥行き移動は行いません。詳しい使い方・制約・設計は [全身版の仕様](docs/fullbody/README.md) にまとめています。

開発時の検証:

```sh
npm test
npm run test:browser
npm run test:tracking
```

ブラウザ検証はWindowsのインストール済みChromeを既定で使用します。他の環境ではPlaywrightのChromiumをインストールするか、`CHROME_PATH` で実行ファイルを指定してください。`test:tracking` は実際のMediaPipeモデルを取得して、合成映像とGoogleの公式人物テスト写真で推論・指の状態・GPU→CPUフォールバックを検証します。アプリのブラウザ検証では4fps・220msの検出遅延、手首の保持、腰が映らない胴体、握る・指を伸ばす動作も扱います。実カメラは使用しません。

- ドラッグアンドドロップで任意の VRM ファイルをロードできます。
- Ctrl+左右キーで背景色を変更できます。
- 今のところカメラ選択の UI はありません。需要があれば実装するかも。

複数アバター撮影用の **VRMC Studio**: https://beatweapon.github.io/vrmc/studio/

- 複数のVRMファイルを選択・ドロップして横に並べられます。ファイルはブラウザ内で読み込み、サーバーへ送信しません。再読み込み時は再追加が必要です。
- 「カメラを開始」で、1台のカメラから検出した顔・表情・頭の傾きを全員に反映します（腕・脚の全身追跡は対象外）。
- 並び順・間隔・カメラ構図・背景色を調整し、「ポーズを固定」で動きを止めて「PNGを保存」で撮影できます。背景透過にも対応しています。
- カメラを使わず、VRMを配置するだけでも撮影できます。StudioはWebSocketサーバーへの接続が不要です。

フロントエンドは `docs/index.html` と `docs/party/index.html` の import map から CDN の固定バージョンを読み込みます。更新時は両画面を揃え、MediaPipe の JavaScript と WASM も同じバージョンにしてください。HTML の更新に合わせて `docs/service-worker.js` の `CACHE_NAME` も更新します。

WebSocket サーバーは `server` ディレクトリで `npm ci`、`npm start` を実行して起動します（ポート 3000）。Node.js 24.18.0 で動作確認しています。パーティ画面の接続先は `docs/party/wsClient.js` の `SERVER_URL` で指定します。
